Three modern directions for Donut

Each option is a complete visual system: logo and app icon, colour and type tokens, shapes, motion, a component set and six sample screens built from the app's real features (matchmaking, the games feed, the leaderboard, profile and match history). Pick one, or mix parts, then hand the implementation brief to an agent.

Where the app is today

  • Launcher shows "CPEN321 Application" with the stock Android icon (res/values/strings.xml, res/drawable/ic_launcher_*.xml).
  • A good base palette already exists: CourtGreen #1E5B3A, BallYellow #D7E84B and green-tinted "Mist" neutrals (core/ui/theme/Color.kt).
  • Type is system Roboto, with Roboto Condensed Bold headlines (Type.kt).
  • Screens use stock Material 3 parts (Card, TabRow, SegmentedButton, AlertDialog, NavigationBar), so they read as generic. Win/loss colours are hard-coded in MatchOutcomeBadge.kt.
  • Tabs: Profile · Matchmaking · Leaderboard · Games.

What every option keeps

  • The name. In tennis a 6–0 set is called a "bagel", a ring-shaped zero. All three logos fuse that ring (the donut) with a tennis-ball seam.
  • The data. Screens only show what the backend already returns, or what the app can work out from it (see data notes).
  • Material 3 underneath. Every colour maps to an M3 colour role, so the work is mostly theme and component code, with no rewrite.
  • Light and dark. Every option ships both. Use the toggle on each option to switch its previews.

Option A

Baseline

Quiet, Swiss-clean and data-forward. Ratings, scores and start times do the talking. A near-monochrome interface with one court-green signal colour and monospaced numbers.

Mood
Calm · precise · premium · light-first
Feels like
A well-made fitness or finance app: lots of air, hairlines, no decoration that doesn't carry information.
Choose it if
You want the most timeless look, the cheapest build and the lowest risk of looking dated in a year.
Trade-offs
Least "sporty". It relies on exact spacing and type, so sloppy padding shows immediately.
Signature moves
Geist Mono for every number that matters · 1 dp hairline borders, no shadows · inset grouped lists · ink-black pill buttons · dark "You" pill pinned on the leaderboard · rating sparkline on Profile.
Copy tone
Plain and short, in sentence case: "Find a match", "Accept by 6:00 PM", "1 spot left".
Icons
Material Symbols Outlined, weight 300, filled when selected.

Option B

Night Session

Prime-time energy. Dark, condensed and italic, like a broadcast scoreboard in your pocket. Optic-yellow on near-black, with skewed tags that suggest speed.

Mood
Bold · competitive · fast · dark-first
Feels like
A sports-broadcast graphics package, or a modern sportswear app.
Choose it if
You want the app to feel competitive and exciting, leaning into ratings, form and rivalries. This fits the product brief ("competitive tennis") most closely.
Trade-offs
Dark-first, so the light theme is the weaker one. Uppercase labels need care with tests and screen readers. The neon yellow must stay a highlight and never become a large background, or it tires the eye.
Signature moves
Optic yellow #DCFF3A on #07090A · parallelogram tags and segmented items · radar on Matchmaking · full-screen "Match found" VS takeover with an accept countdown · scoreboard-style history · form guide (W L W W W) · fixture-list game cards.
Copy tone
Punchy uppercase for labels and buttons ("FIND A MATCH", "ACCEPT"). Body text stays in sentence case.
Icons

Implementation brief

Written for the agent or developer who builds the chosen option in frontend/. It applies to every option; option-specific code is in each option's "Compose code" block, generated from TOKENS.

Prompt to hand to an agent 
Implement design Option <A | B | C> ("<Baseline | Night Session | Clubhouse>") from
documentation/design/design-directions.html in the Android app under frontend/.

Read, in that file:
  1. The section with id "option-<a|b|c>" for the concept, rules, components and screens.
  2. const TOKENS in <script id="tokens">. It is the source of truth for colours, type, shapes,
     spacing, motion and icons. The "Compose code" block in the option section is generated from it.
  3. The templates in <script id="render"> (object R.<A|B|C>) for exact layout and token use.
  4. The section with id "handoff": constraints, phases, file map, data notes, acceptance checklist.

Work in the phases in the brief, and build and run the tests after each phase.
Do not change any version in frontend/gradle/libs.versions.toml and do not add libraries
unless the brief allows it. Keep the strings that androidTest asserts, or update those tests in the
same change. Open the app in the emulator and compare each screen against the mockup in both themes.

Hard constraints

  • Frozen toolchain. libs.versions.toml pins AGP 8.13, Kotlin 2.1.21, compileSdk 35 and Compose BOM 2025.06.01, which gives Material 3 1.3.x. Do not bump anything. M3 Expressive APIs (MaterialExpressiveTheme, ButtonGroup, LoadingIndicator, FloatingToolbar, shape morphing) are not available. Build those looks by hand.
  • Fonts are bundled, not downloadable. Put static TTFs (all SIL Open Font License, free to bundle) in app/src/main/res/font/ with the exact file names listed in the option's Type.kt, and commit the OFL text (e.g. documentation/licenses/OFL-<family>.txt). Don't add ui-text-google-fonts.
  • Icons. Today's Icons.Default.* come from material-icons-core, which Material 3 1.3 pulls in. Don't add material-icons-extended (it's very large). Download each Material Symbol the option uses from fonts.google.com/icons in the option's style, weight and fill, as Android vector drawables named ic_<name>.xml / ic_<name>_filled.xml, and draw them with painterResource.
  • minSdk 26. Coloured shadows (Modifier.shadow(spotColor=…)) only show on API 28+. Treat them as decoration that can quietly disappear.
  • No dynamic colour. Keep brand colours fixed, as Theme.kt does today.
  • Keep the theme function's name, CPEN321ApplicationTheme (used by MainActivity.kt), or rename it everywhere in one change.

Optional changes the mockups assume (fine to skip)

  • Tab order and names: Play · Games · Leaderboard · Profile, renaming "Matchmaking" to "Play". Only titles, icons and list order in BottomNavItem.kt / AppBottomBar.kt change; keep the route strings.
  • Sign out moves from a big button on Profile to a settings icon in the Profile top bar (a menu or a small settings screen).
  • Match found becomes a ModalBottomSheet (A, C) or a full-screen takeover (B) instead of an AlertDialog. Keep today's rules: it can't be dismissed without answering, and it moves to "Waiting for …" and then "Game on" states.

Tests that pin text (keep these strings or update the tests)

  • LeaderboardScreenTest: "#1", "@player1", "1988", "Player 3 (You)", "No players yet", "Retry". The mockups keep the #N rank format and the "(You)" suffix for this reason. Moving "You" into a chip means updating lines 66–93.
  • TournamentDetailScreenTest: "Join tournament", "Leave tournament", "Cancel tournament", "Registered players", "Quarterfinals", "Semifinals", "Final", "Champion", "3/8 players".
  • Option B uses uppercase labels. Compose has no text-transform, so uppercasing means calling .uppercase() on the string, which changes the text the tests see. Either keep test-asserted strings in mixed case or update the assertions. TalkBack reads uppercase strings fine.

Acceptance checklist

  • Every colour comes from MaterialTheme.colorScheme or DonutTheme.colors; there are no Color(0x…) literals in feature code.
  • Every text style comes from MaterialTheme.typography or DonutTextStyles; ad-hoc fontWeight/fontSize overrides in screens are removed.
  • Light and dark both checked on every screen; body text contrast ≥ 4.5:1 and large text ≥ 3:1 (the token pairs below were chosen to pass).
  • Touch targets ≥ 48 dp; icon-only buttons have a contentDescription; decorative art (court lines, radar, sprinkles) has none.
  • Layouts hold at font scale 1.3 and at 360 dp width. Long court and player names ellipsize and don't wrap the layout.
  • Animations respect the system "remove animations" setting (check Settings.Global.ANIMATOR_DURATION_SCALE, or use the reduced-motion fallback described in the motion tokens).
  • The launcher icon passes Android Studio's adaptive-icon preview (circle, squircle, teardrop) with the mark inside the 66 dp safe zone.
  • ./gradlew test and connectedAndroidTest pass.
